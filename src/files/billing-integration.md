# Billing Details — передача WordPress-розробнику

Це HTML/SCSS/JavaScript-інтерфейс. Дані користувача, платіжні токени, збереження, видалення, вибір основного методу та інтеграцію WooCommerce підключає WP-розробник.

## Сторінки для перевірки

| Сторінка | Початковий стан |
| --- | --- |
| `billing.html` | Немає збережених карток |
| `billingcard.html` | Одна картка Visa з позначкою Default |
| `billingcards.html` | Visa Default і Mastercard з дією Make default |
| `billingaddcard.html` | Дві картки та відкрита форма додавання |

Усі сторінки використовують `components/pages/billing/` і `components/custom/billingsection/`. Початкові приклади передаються через HTML locals `paymentState.cards` та `paymentState.isFormExpanded`. Окрема картка винесена в `components/custom/paymentmethodcard/paymentmethodcard.html`; вона використовує стилі `paymentmethods.scss`. Дані прикладів призначені для перевірки верстки.

## Що працює в інтерфейсі

- Individual / Company перемикає поля компанії, їх доступність та анімацію панелі.
- Add payment method відкриває форму; Cancel / Escape закриває її.
- Поля мають оформлення, маски та перевірку заповнення для перегляду станів помилки.
- Remove і Make default на картці відкривають відповідні модалки.
- Зміна billing-полів і клік на посилання відкривають Leave without saving.
- Cancel / Keep editing / Escape закривають модалки з анімацією та поверненням фокуса.

**Підтвердження Remove, Make default і Leave page — звичайні `type="button"` без обробників і службових результатів. Вони нічого не видаляють, не змінюють Default, не закривають модалку, не відправляють подій і не виконують переходів.**

## Спільна модалка

`components/custom/confirmationmodal/` містить спільні HTML, SCSS і `createConfirmationModal(dialog)`.

Контролер надає лише `open(trigger)`, `close()` і `destroy()`. `data-confirmation-cancel` потрібний для кнопки закриття. На підтвердженні немає `data-confirmation-result`, власного результату чи готової дії. Закриття чекає фактичного завершення анімації; reduced motion враховано.

Платіжні кнопки `data-payment-action="remove"` і `data-payment-action="default"` використовуються виключно для відкриття модалок. У верстці немає action URL, token ID, `paymentMethodConfirm`, запиту до платіжного сервісу чи локального збереження карток. WP-розробник сам визначає обробку підтвердження та момент закриття.

## Форми та інтеграція

Billing-форма та форма додавання платіжного методу окремі. `data-ui-preview-form` зупиняє їх надсилання й дозволяє перевірити помилки полів. Після підключення WooCommerce замінити демонстраційні дані та обробку форм; зберегти класи, label/ID/ARIA-зв’язки, окремі форми та абсолютне позиціонування повідомлень помилок.

Поля номера картки й CVC не мають `name`, не надсилаються та не зберігаються. Вони показують оформлення форми. Реальні платіжні поля й обробку надає встановлений gateway.

`data-billing-unsaved-guard` вмикає порівняння billing-полів із початковими значеннями та відкриття попередження. Вибір країни під час ініціалізації враховується в початковому стані. Leave page не має дії; обробку підтвердженого виходу реалізувати під час WP-інтеграції. Браузерне попередження при reload / закритті вкладки залишається для змінених полів.

Країни, вимоги до адреси, податки, nonces, авторизацію та серверні повідомлення визначає WooCommerce і встановлені плагіни. Готових backend endpoints або власного контракту платіжних дій у верстці немає.

Зберегти наявний компонент select або замінити його на компонент WooCommerce. Не ініціалізувати два різні select-компоненти на одному полі. Скрипти й стилі збірки потрібно підключити у WordPress зі збереженням залежностей; `data-fls-*` самостійно не завантажує модулі поза Vite.
